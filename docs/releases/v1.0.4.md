## 刷新会话列表：数量不再忽多忽少，昵称也不会显示成 uid

抖音的私信列表滑动之后是「两步渲染」：先按 uid 画出一行，过一两秒才换成真昵称。
旧版本滑完就立刻读页面，于是同一个人的 uid 版本也被当成一条新会话收进来 —— 同一份
列表刷新三次，可能是 45 / 94 / 45 个，面板里也有的会话显示成 `100000000…`。
这一版把「滑动之后先停 1 秒」变成固定动作。

### 改了哪些地方

- **每次滑动会话列表之后固定停 1 秒再读页面**（刷新会话列表、采集时滚动找会话都走这一条）；
  如果窗口里还有会话显示着 uid 标题，就继续等，最多约 5 秒 —— 昵称渲染出来就走，不白等；
- **滚到底不再「立刻收工」**：原来连续两轮没有新会话就停，而抖音刚贴底的那一两轮往往只是
  「还没画出来」，于是只收到一半（94 个只收到 45 个）。现在要连续三轮都「滚不动 + 没新增」，
  还要再多读一轮确认；贴底时也顺手把滚动条顶到最新高度，催抖音继续拉下一页；
- **顺手修的小问题**：会话名里的排版空格（`\xa0`）在去重之前就统一成普通空格，
  不会再因为空格差异把同一个会话算成两条；
- **昵称本身就是一串数字的号**（不是没渲染出来，是人家真没昵称）：会话照常收进列表、
  照常能勾选采集，只是第一次会多等一下确认，之后就不再为它空等；刷新日志也会说清楚
  「可能是抖音还没渲染出昵称，也可能对方昵称本来就是数字」，让人自己判断。

### 顺带做的小事

- 「滑动一次等 1 秒」会让翻完整份列表变慢，所以采集时找会话的超时从 15 秒放宽到 40 秒
  （够从头翻到底一遍），免得长列表末尾的会话被误判成「找不到」；
- 采集页那句「点击"刷新会话列表"加载全部会话…」以前在页面上显示了两遍，现在只留页面说明那一遍；
- README 的「为什么刷会话列表 / 开始采集要等一会儿」补上「每次滑动后等 1 秒」这一条，
  并把三处等待整理成一张表；
- 新增 `tests/test_conv_list_scroll_settle.py`：钉住「滑动后先等昵称、再读 DOM」、
  「滚到底要等抖音异步补页」，以及「昵称本身就是数字的号不会被丢掉、也不会被反复空等」。
