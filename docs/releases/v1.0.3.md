## 双击启动：看得见的进度，不再像个卡死的黑窗口

以前双击 `启动服务（双击）.bat`，那个黑窗口只留一句「正在后台启动」就立刻关掉，真正干活的是
另一个隐藏窗口。首次启动要建虚拟环境、装依赖、构建前端，好几分钟里屏幕一点动静都没有，
很容易被当成卡死。这一版让双击后的窗口留下来，一直显示进度。

### 双击后能看到什么

- 实时显示**当前在做哪一步**（建虚拟环境 → 装 Python 依赖 → 装前端依赖 → 构建前端 → 起服务），
  每一步还带一句「这步大概要多久」的提示；
- 每一步下面有一行**已等待时间**（每 2 秒刷新，带转动的小符号），一眼就能看出程序还活着；
- 服务就绪后自动打开控制面板，窗口提示 8 秒后自动关闭（按任意键立刻关闭）；
- 这个窗口只是进度显示：最小化、关掉都不影响后台服务；停止服务仍然用面板 **日志 → 停止程序**。

### 启动失败时不再让人猜

- `start.ps1` 中途退出（没装 Node.js、Python 版本过低、网络装不上依赖等）时，窗口会**停下来**，
  显示退出码，并把启动日志的最后几行直接贴出来，同时给出完整日志路径和手动重试命令；
- 等满 30 分钟还没起来也会停下来显示日志，并提醒「先别急着重开 —— 重新双击会再启动一个安装过程」。

### 双击时那个「无法验证发布者」的框

从网上下载的 ZIP 解压出来的项目，Windows 会给文件盖一条「来自 Internet」的下载标记；带标记的
`.bat` 被打开时系统会先弹「无法验证发布者。你确定要运行此软件吗？」。这一版做了三件事：

- **后台那次启动不再经过 Windows 的「关联打开」**：原来双击 bat 后，它还会用「关联打开」把自己
  再拉一次（真正干活的那次），带标记时这一步会**再弹一个框，而且弹在隐藏窗口里** —— 不点它服务
  根本起不来（「明明点了运行还是卡住」多半就是它）。现在这一步改由 `cmd.exe` 拉起，系统不做这个
  检查，所以只有你自己那一次双击会看到框；
- **启动后自动清掉这个标记**：后端起来时清一遍整个项目（新增 `common/download_mark.py`），
  `start.ps1` 另外先把项目根目录那一层清掉 —— 工具自己跑过一次之后，以后双击不再弹；
- 只清会弹框的扩展名（`.bat` / `.ps1` / `.exe` 等），`.py` / `.md` 留着也不碍事；非 Windows
  系统没有这回事，相关函数是空操作。

**第一次**那个框代码拦不住：Windows 是在我们跑起来之前就问的。所以第一次点一下「运行」即可，
或者先跑 `start.html`（它不会触发这个框）。

### 万一安全软件拦住了 PowerShell，也不会「一闪而过」

- 有些电脑上 Windows Defender 的 AMSI 会偶发崩溃（屏幕上是一大段 .NET 异常，和项目本身
  无关）。遇到这种情形，双击后的窗口会**先自动重试一次**，仍然不行就退回**纯命令行的简易
  等待**：每 3 秒一个点，服务起来后照样自动打开控制面板；
- 简易等待也会识别「启动脚本已经退出」，不会对着一个已经死掉的启动过程无限等；超时或失败
  都会把日志路径说清楚，然后停住等回车。

### 实现与文档

- 新增 `tools/launcher_progress.ps1`：可见窗口里的进度显示；`启动服务（双击）.bat` 把
  「隐藏启动」和「窗口显示进度」两件事分别拉起来；
- 进度脚本读 `config/logs/launcher.log`：那份日志在启动过程中一直被占用，所以用
  `FileShare.ReadWrite` 打开；并且只认「比本次启动更新的内容」，不会把上一次启动的旧步骤
  当成本次；
- `start.ps1` 的 `=====> 步骤` 前缀成了进度显示的锚点（注释里写明别去掉）；
- 进度脚本给 bat 的退出码是约定（0 就绪 / 2 超时 / 3 启动失败），别的码表示它自己没跑起来；
- 新增 `common/download_mark.py`（清下载标记）和 `tests/test_download_mark.py`；
- README 同步说明双击后的窗口行为、以及第一次可能出现的「运行」询问；测试补上「可见窗口跑
  进度脚本」「`chcp 65001` 之后必须纯 ASCII」「bat 和进度脚本的退出标记、退出码一致」
  「PowerShell 被拦时有 cmd 兜底」「隐藏启动不走 Windows 关联打开」等用例。
