## 不再把语音「识别统计」当成错误弹框

采集跑起来后，面板会一边跑一边看日志：只要某行以 `[voice]` 开头、里面又出现「失败」
两个字，就认定有语音下载失败，弹出「采集遇到错误」，并把采集进程一起冻住等你处理
（倒计时 2 分钟才自动继续）。而语音转写干完活会打印这么一行汇总：

```
[voice] 识别统计: 总数=47 缓存=0 请求=47 成功=47 失败=0 跳过=0
```

47 条语音全部成功、失败数明明是 0，但因为这行文字里带着「失败」两个字，被当成了失败
——于是白弹一个框、白冻两分钟。弹框里的「错误内容」又只是最后 60 行日志，全是正常记录
（日志停在「归一化消息序号」正是因为进程被冻住了），看起来莫名其妙。

### 改了哪些地方

- 汇总行里的「失败=0」不再算错误：`识别统计`、`回填会话完成`、`历史回填完成` 这几行
  都会豁免；`已下载 N 个 (失败 0)` 这条早就有豁免，这次把语音那几行补齐；
- 失败数不为 0（例如 `失败=3`）**仍然照报**——逐条语音失败没有单独的日志行，那行汇总
  是唯一的信号，不能整行忽略；
- 顺手钉住一个边界情况：服务器 ID 恰好以 0 开头时（`[voice] 下载失败: 0769…`），
  不能被当成「失败=0」而漏报；
- `tests/test_panel_job_errors.py` 补了 6 条断言覆盖上面几种情况。

### 说明

- 这次误报只影响面板的判断和那 2 分钟冻结，采集到的消息、语音、图片都没有丢；
- 改动在 `backend/control_panel.py`，升级后**要重启一次服务**才会生效。
