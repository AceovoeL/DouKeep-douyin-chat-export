## 公开仓库不再要求填凭据

仓库公开之后，检查更新和自动更新都不该再拿「私有仓库凭据」当门槛。这一版把两处都改对了。

### 检查更新

- **修掉一个 Windows 上必现的报错**：打开开发者模式、又没填凭据时，程序会去用本机的
  `git fetch` 问远端；而它给 git 子进程准备的环境把整个环境变量换成了只有两个变量，git
  因此丢掉 `SystemRoot`，连 `github.com` 都解析不了（`Could not resolve host`）。这个失败
  最后被笼统地报成「需要 GitHub 凭据才能读取私有仓库」——仓库明明是公开的。现在这两个
  变量是**叠加**在原有环境上的。
- **没凭据也会试一次匿名接口**：以前没有凭据就只走本地 git，git 拿不到就报「缺凭据」。
  现在 git 不行时还会用**不带凭据**的方式读 GitHub 接口 —— 公开仓库本来就允许匿名读。
  只有 git 明确说「要凭据」（私有仓库）时，才提示去填 Token。
- 「读不到更新源」的提示改成把两种可能都说出来：仓库可能还没公开，或私有仓库需要先填只读 Token。

### 下载代码包更新（目录里没有 git 时）

- **有凭据就用凭据，没有就匿名下载**，不再一上来就拦下来要 Token；日志里会写清这次是
  「带凭据」还是「不带凭据」。
- 带的凭据被拒（401/403，例如 Token 过期）时会**自动退回匿名再下一次**，不因为凭据失效
  就让更新彻底失败。
- 只有两次都下不到才停下，并且按实际情况给提示：没填过凭据 → 去填只读 Token；存过 Token
  但开发者模式关着 → 去打开开发者模式（不会让人以为 Token 丢了又粘一遍）；有凭据还是被拒
  → 凭据可能无效或没权限。
- 开发者模式的作用收窄为「用不用那份凭据」，不再决定「能不能用下载的方式更新」。

### 其他

- README 同步更新：检查更新、下载代码包覆盖两条路都写明「公开仓库不需要凭据，只有私有仓库才要」。
- 新增 10 个回归测试（匿名接口兜底、git 环境变量必须保留父进程环境、匿名下载不带
  `Authorization` 头、凭据被拒自动重试、两种失败提示各一）。
