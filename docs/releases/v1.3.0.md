## 新增「纯文本 TXT」导出：几万条消息也能整份交给 AI

控制面板 **导出/导入** 的格式下拉里多了一项 **纯文本 TXT**（命令行是 `--format txt`）。
文件一条消息一行，只有文字：

- 文字消息写成 `[昵称]正文` —— 表情本来就在正文里，例如 `[昵称]今天天气不错[憨笑]`；
- 分享消息写成 `[昵称][分享视频] 标题`：只留类型和作品标题 / 评论内容，不带作者与跳转
  链接；类型分得清视频 / 图文 / 动图 / 文章 / 评论 / 商品 / 直播 / 限时日常；
- 系统消息写成 `[系统消息] 内容`（这类消息没有发送者，所以不写昵称；只有标签、没有
  内容的空通知不占一行）；
- 图片、语音、视频只有 `[图片]`、`[语音 3秒] 转写文字`、`[视频 12秒]` 这样的标签，
  不内嵌任何文件；合并转发的正文按发送者写成几行。

**为什么加它**：以前只有 JSON / JSONL，图片还会内嵌成 base64，一个上万条消息的会话动辄
几十 MB，丢给 AI 分析既慢又占上下文。实测同一个 1 万条消息的会话：JSONL 62 MB，
TXT 0.5 MB。文件名同样是 `会话昵称_YYYYMMDDHHMMSS_export.txt`。

### 其他改动

- 分享卡片的类型判定（视频 / 图文 / 动图 / 文章 / 评论 / 商品 / 直播 / 限时日常）搬进了
  `common/message_kinds.py`，与面板搜索结果里那一行用的是同一套规则；
- README 的导出一节重写了：先给三种格式的命令，再分别说清各自导出什么、体积差多少；
- 面板选中 TXT 时会显示一行说明，中英文都有；
- **一个会话都没勾时不再「替你挑一个」**：以前这种请求会被当成「没指定」，顺手导出最近
  活跃的那一个会话（实测挑中过 2.8 万条消息、509 MB 的会话，看着像"什么都没勾却导出了
  一大堆"）。现在「导出」按钮先置灰，会话列表上方写明要先勾选；接口也会直接返回 400。
  整库导出（SQLite）本来就不看勾选，不受影响。
- 顺手做了一次脱敏检查：仓库里有几处样例是从真实聊天记录里抄来的，已换成一眼可辨的假
  数据（一个真实昵称、一条真实消息正文、一张商家联系卡的两行文案）。抖音自己的表情名和
  系统通知模板（`assets/emoji_manifest.json` 与消息解析规则里那些）保持不变 —— 那些是
  平台文案，认不出来就没法渲染。

### 升级说明

- 更新后重启一次服务（面板 → **日志** → **重启服务**）。
- 原来的导出方式没有变化：JSONL / JSON 的内容、文件名、下载方式都和以前一样。
- 只有 `[系统消息]` 标签、没有任何正文的空壳通知（抖音只发了个通知壳，面板里本来也
  不显示这种消息）不再白占一行；JSON / JSONL 导出不受影响，照旧保留这些消息。
