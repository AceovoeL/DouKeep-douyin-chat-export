## 修好「把解析改到这台电脑」：点了不生效，还骗你说改好了

### 出了什么事

域名在 Cloudflare 上**已经指向另一条隧道**（同一个账号下还挂着别的服务时很常见）的时候，
打开域名看到的是 Cloudflare 的 **404 空页面**。而面板里那个 **把解析改到这台电脑** 按钮
点了也没用：

cloudflared 撞上这种记录时**连 `--overwrite-dns` 都不覆盖**，只打一句
「… is already configured to route to your tunnel tunnelID=…」（报的是**那条别人的**隧道），
然后**照样退出 0**。程序只看退出码，于是把它当成功 —— 挂载时谎报「解析已建好」，
点按钮时谎报「覆盖了原有记录」，还把该留的警告一起收掉了。
结果就是：面板一切正常，域名打不开。

### 这一版改了什么

1. **「把解析改到这台电脑」现在真的会改**：不再指望 cloudflared 的命令行，改成直接调
   Cloudflare 接口，把那条 `CNAME → *.cfargotunnel.com` 的记录内容改成本机隧道。
   只动这一种记录 —— 域名上你自己的 A / TXT / MX 之类一概不碰。
2. **认出 cloudflared 那句「假成功」**：输出里说「已经指向某某隧道」而那条隧道不是本机时，
   不再算成功。挂载会亮出黄色提示，按钮会老实报失败并说明去哪儿手动改。
3. **设了访问密码后，第 6 步「回头看」不再误报失败**：以前公网请求会先被访问密码那道门
   拦住、回一句 `lan_access_password_required`，程序把它当成「域名没回到本机」。而
   **挂着公网 + 设了访问密码**恰恰是推荐用法，于是这一步几乎必然报错。现在这句回复
   也算「请求已经到达本机」。
4. 面板那两句提示（中英）改写得更直白。

### 升级说明

- 更新后重启一次服务（面板 → **日志** → **重启服务**）。
- 如果你的域名现在指向的是别的隧道：面板 → **设置 → 局域网访问 → 公网访问**，
  点 **把解析改到这台电脑**。上一版点过没反应的，这一版再点一次就真会改。
